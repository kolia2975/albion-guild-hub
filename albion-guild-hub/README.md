# Albion Guild Hub

Гільдійський сайт економіки + КТА для Albion Online: острови й робітники,
переробка/крафт (RRF), арбітраж, ефективність фокусу, гільдійський острів,
сети/білди з авто-підбором за майстерками, скарбниця, ролі доступу,
нотифікації на сайті + в Discord.

**Стек:** PostgreSQL + Node.js/Express (API) + звичайний HTML/CSS/JS
(Alpine.js, без збірки) + Discord-бот (discord.js). Все загорнуто в
Docker, тому команда запуску абсолютно однакова і на твоєму ПК, і
пізніше на Proxmox-сервері.

## 1. Що таке Docker і чому саме він

Уяви Docker як "коробку", в яку запаковано програму разом з усім, що їй
потрібно для роботи (Node.js, бібліотеки, налаштування). Коробка працює
однаково на будь-якому комп'ютері — на твоєму ПК, на ноутбуці друга,
на сервері Proxmox. Не потрібно окремо ставити Node.js, PostgreSQL і
налаштовувати їх вручну — Docker сам підніме всі 4 "коробки" (контейнери)
проєкту та з'єднає їх у мережу:

| Контейнер | Що робить |
|---|---|
| `db` | База даних PostgreSQL — тут зберігається абсолютно все |
| `app` | Node.js API + віддає сайт (HTML-сторінки) |
| `bot` | Discord-бот — слеш-команди + нотифікації в канал |
| `adminer` | Веб-переглядач бази даних (зручно дивитись таблиці в браузері) |

Файл `docker-compose.yml` — це "рецепт", який каже Docker, як зібрати ці
4 контейнери в одну систему. Саме тому переїзд на Proxmox пізніше — це
буквально копіювання папки проєкту і одна команда `docker compose up -d`.

## 2. Встановлення на ПК (Windows)

1. Встанови **Docker Desktop**: https://www.docker.com/products/docker-desktop/
   - Під час встановлення обов'язково постав галочку **"Use WSL 2 instead
     of Hyper-V"** (Docker сам запропонує).
   - Після встановлення — перезавантаж ПК.
2. Відкрий Docker Desktop і дочекайся, поки в лівому нижньому куті
   з'явиться зелений напис **"Engine running"**.
3. Встанови текстовий редактор, якщо ще нема — **VS Code**:
   https://code.visualstudio.com/ (щоб зручно редагувати `.env` і
   HTML-сторінки).
4. (Опційно, але зручно) Встанови **Git**: https://git-for-windows.github.io/
   — знадобиться, якщо будеш зберігати проєкт у GitHub/GitLab для
   зручного перенесення на сервер пізніше.

Перевірка, що все встановилось — відкрий **PowerShell** і виконай:

```powershell
docker --version
docker compose version
```

Якщо обидві команди показали номер версії — все ок.

## 3. Перший запуск проєкту

1. Розпакуй архів `albion-guild-hub.zip` у будь-яку зручну папку, напр.
   `C:\Projects\albion-guild-hub`.
2. Відкрий цю папку в PowerShell (правий клік у провіднику всередині
   папки → "Відкрити термінал тут").
3. Скопіюй файл прикладу середовища:
   ```powershell
   copy .env.example .env
   ```
4. Відкрий `.env` у VS Code і заміни **мінімум** ці значення на свої:
   - `POSTGRES_PASSWORD` — будь-який складний пароль
   - `JWT_SECRET` — довгий випадковий рядок (можна просто настукати
     50 випадкових символів)
   - `ADMIN_BOOTSTRAP_LOGIN` / `ADMIN_BOOTSTRAP_PASSWORD` — логін/пароль
     твого першого адмін-акаунта на сайті
   - `BOT_INTERNAL_API_KEY` — будь-який випадковий рядок (просто
     "пароль" для зв'язку бота з бекендом)
   - Discord-змінні (`DISCORD_BOT_TOKEN` і т.д.) — заповниш у [розділі 4](#4-discord-бот-створення-і-підключення).
     Без них сайт і так запуститься, просто бот не стартоне.
5. Запусти весь стек:
   ```powershell
   docker compose up -d --build
   ```
   Перший раз це займе кілька хвилин (Docker скачує образи та збирає
   контейнери). У кінці має написати щось на кшталт `Container albion_app  Started`.
6. Перевір, що бекенд живий:
   ```powershell
   curl http://localhost:4000/api/health
   ```
   Має повернутись `{"ok":true,...}`.
7. Відкрий у браузері **http://localhost:4000** — побачиш сторінку входу.
8. Увійди логіном/паролем з `ADMIN_BOOTSTRAP_LOGIN` / `ADMIN_BOOTSTRAP_PASSWORD`.
   Одразу зайди в "Мій профіль" → зміни пароль на постійний.
9. У розділі "Адмінпанель" створи акаунти для інших учасників гільдії й
   вистав їм ролі (гільд-юзер / економіст / обліковець / кістяк файтів /
   модератор / адмін).

**Переглянути базу даних у браузері:** http://localhost:8081 (Adminer) →
"Система": PostgreSQL, "Сервер": `db`, далі логін/пароль/назва бази —
ті самі, що в `.env`.

## 4. Discord-бот: створення і підключення

1. Зайди на https://discord.com/developers/applications → **New Application**.
2. Дай назву (напр. "Albion Guild Hub") → **Create**.
3. Зліва → **Bot** → **Add Bot** (якщо ще не створено автоматично).
4. Там же натисни **Reset Token** → скопіюй токен → встав у `.env` як
   `DISCORD_BOT_TOKEN`.
5. Зліва → **OAuth2 → URL Generator**:
   - Scopes: постав галочку `bot` і `applications.commands`
   - Bot Permissions: `Send Messages`, `Embed Links`, `Read Message History`
   - Знизу згенерується посилання — відкрий його і додай бота на свій
     Discord-сервер гільдії.
6. У Discord: **Налаштування користувача → Розширені → увімкни Режим
   розробника (Developer Mode)**.
7. Правий клік на своєму сервері → **Copy Server ID** → встав у `.env`
   як `DISCORD_GUILD_ID` (це для миттєвої появи слеш-команд лише на
   твоєму сервері, а не очікування до години глобально).
8. Правий клік на каналі для нотифікацій → **Copy Channel ID** → встав
   у `.env` як `DISCORD_NOTIFY_CHANNEL_ID`.
9. Із **Developers Portal → General Information** скопіюй **Application ID**
   → встав у `.env` як `DISCORD_CLIENT_ID`.
10. Перезапусти тільки бота, щоб підхопив нові змінні:
    ```powershell
    docker compose up -d --build bot
    ```
11. У Discord набери `/status` — бот має відповісти зведенням по гільдії.

## 5. Щоденна робота: логи, перезапуск, редагування

```powershell
# Подивитись, що відбувається (логи всіх контейнерів наживо)
docker compose logs -f

# Логи тільки бекенду
docker compose logs -f app

# Перезапустити все після зміни .env або коду бекенду
docker compose up -d --build

# Зупинити все (дані в базі НЕ видаляються)
docker compose down

# Зупинити І ВИДАЛИТИ дані бази (обережно!)
docker compose down -v
```

**Редагування фронтенду (HTML/CSS/JS у папці `frontend/`):** контейнер
`app` бачить цю папку "наживо" — просто зберігаєш файл у VS Code і
оновлюєш сторінку в браузері (Ctrl+F5). Перезапуск контейнера НЕ потрібен.

**Редагування бекенду (`backend/src/...`):** оскільки бекенд копіюється
у Docker-образ під час збірки (а не монтується наживо), після зміни
JS-файлів бекенду потрібно перезібрати:
```powershell
docker compose up -d --build app
```

## 6. Резервні копії бази даних

Робити бекап **регулярно**, особливо перед великими змінами:

```powershell
docker compose exec -T db pg_dump -U albion albion_guild_hub > backup.sql
```

(заміни `albion` і `albion_guild_hub` на свої значення з `.env`, якщо
змінював за замовчуванням).

Відновлення з бекапу:

```powershell
docker compose exec -T db psql -U albion -d albion_guild_hub < backup.sql
```

## 7. Перенесення на Proxmox

Головна ідея: усе, що ти робив на ПК, — це папка проєкту + Docker.
На Proxmox потрібно просто мати Linux-машину з Docker і скопіювати туди
ту саму папку.

### Варіант А — LXC-контейнер з Docker (легше, менше ресурсів)

1. У Proxmox: **Create CT** → шаблон **Ubuntu 22.04/24.04** або **Debian 12**.
2. У вкладці **Options** увімкни **Nesting = 1** (це дозволяє Docker
   працювати всередині LXC).
3. Запусти контейнер, зайди в консоль і встанови Docker:
   ```bash
   curl -fsSL https://get.docker.com | sh
   apt install -y docker-compose-plugin
   ```

### Варіант Б — Повноцінна VM (надійніше, якщо є вільні ресурси)

1. Створи VM з Ubuntu Server 24.04 (звичайна установка).
2. Встанови Docker так само командою вище.

### Перенесення проєкту та даних

1. На ПК зроби бекап бази (`docker compose exec -T db pg_dump ...`, див.
   [розділ 6](#6-резервні-копії-бази-даних)) — файл `backup.sql`.
2. Скопіюй усю папку проєкту (крім `node_modules`, яких там і не має
   бути) на сервер. Найпростіше — через **WinSCP** (Windows) або
   `scp -r` з PowerShell:
   ```powershell
   scp -r C:\Projects\albion-guild-hub root@IP_СЕРВЕРА:/opt/albion-guild-hub
   ```
3. На сервері зайди в папку і онови `.env`:
   ```bash
   cd /opt/albion-guild-hub
   nano .env
   ```
   Зміни `PUBLIC_URL` на реальну адресу (домен або `http://IP_СЕРВЕРА:4000`).
4. Підніми стек:
   ```bash
   docker compose up -d --build
   ```
5. Заллий бекап бази (якщо переносиш існуючі дані, а не починаєш з нуля):
   ```bash
   cat backup.sql | docker compose exec -T db psql -U albion -d albion_guild_hub
   ```

### Домен + HTTPS (рекомендовано для постійної роботи)

Постав перед `app` реверс-проксі з автоматичним SSL — найпростіше
через **Nginx Proxy Manager** (окремий контейнер з веб-інтерфейсом):
1. Додай ще один сервіс `nginx-proxy-manager` у `docker-compose.yml`
   (образ `jc21/nginx-proxy-manager`) АБО постав його окремим
   LXC-контейнером з довідки Proxmox Community Scripts.
2. Прив'яжи свій домен (напр. `guild.твійдомен.com`) до IP сервера
   через A-запис у DNS.
3. У Nginx Proxy Manager створи Proxy Host: домен → `http://albion_app:4000`
   (або `http://IP_СЕРВЕРА:4000`, якщо NPM не в тій самій docker-мережі),
   увімкни "Request a new SSL certificate" (Let's Encrypt).

Без власного домену сайт так само працюватиме по
`http://IP_СЕРВЕРА:4000` у локальній мережі гільдії/дому.

## 8. Ролі доступу — хто що може

| Роль | Доступ |
|---|---|
| **Гільд-юзер** (member) | Свій профіль, свої розрахунки, перегляд сетів/нотифікацій |
| **Економіст** | + збереження розрахунків переробки/арбітражу/фокусу |
| **Обліковець** | + повний доступ до скарбниці (журнал приходу/витрат) |
| **Кістяк файтів** (roster) | + створення/редагування сетів, перевірка готовності складу до КТА |
| **Модератор** | + керування користувачами (крім видачі ролей moderator/admin), оголошення, таймери |
| **Адмін** | Повний доступ до всього, включно з гільдійським островом і роллю moderator/admin |

Логіка описана у `backend/src/middleware/roles.js` — щоб додати новий
дозвіл чи змінити, кому що можна, редагуй список `PERMISSIONS` у цьому
файлі.

## 9. Типові проблеми (troubleshooting)

**"port is already allocated"** — щось інше на ПК вже займає порт 4000/5432/8081.
Зміни зовнішній порт у `docker-compose.yml`, напр. `"4001:4000"` замість
`"4000:4000"`, і заходь тоді на `http://localhost:4001`.

**Бот не відповідає на слеш-команди** — перевір, чи правильно вказані
`DISCORD_BOT_TOKEN`, `DISCORD_CLIENT_ID`, `DISCORD_GUILD_ID` у `.env`,
і подивись логи: `docker compose logs -f bot`.

**Сайт відкривається, але "Не вдалося увійти"** — перевір, чи контейнер
`db` встиг піднятись (`docker compose ps`, статус має бути `healthy`),
і чи збігається `ADMIN_BOOTSTRAP_PASSWORD` у `.env` з тим, що вводиш.
Якщо адмін вже був створений раніше з іншим паролем — зміна `.env` вже
не допоможе, адмін створюється лише один раз при порожній таблиці
`users` (онови пароль через "Мій профіль" або напряму в Adminer).

**Хочу почати з нуля (видалити всі дані)**:
```powershell
docker compose down -v
docker compose up -d --build
```

## 10. Чесно про обмеження цієї версії

Це повноцінний робочий каркас із реальною логікою (RRF-математика,
податки ринку, ROI арбітражу, RBAC, авто-підбір сетів за майстерками,
Guild Island з плотами/будівлями, нотифікації сайт+Discord) — а не
просто макет. Але деякі речі варто розширити самостійно під себе:

- **Ціни ринку**: зараз вводяться вручну в калькуляторах. Публічне API
  Albion Online Data Project (`albion-online-data.com/api/v2/stats/prices/...`)
  легко підключити в `backend/src/services/` для автопідтягування цін —
  залишив таблицю `market_price_cache` саме під це.
  Не всі ринкові дані там завжди доступні. Перевір разом з гільдією умови
  використання, коли будеш підключати.
- **Плоти гільдійського острова**: прогресія кількості плотів по тірах
  1-6 — це наближення (підтверджена лише сума на максимальному тірі:
  1 Large + 16 Building + 2 Small Building). Патчі гри можуть змінити
  точні числа — звіряй з грою і підправляй вручну через інтерфейс.
- **Довідник ліній майстерок і сетів** — засіяно базовим репрезентативним
  набором, доповнюй через адмінку/SQL під повний список предметів гри.
